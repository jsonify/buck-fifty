# Buck Fifty

An iPhone shopping list that learns the store's order from check-offs, shared in real time. `README.md` is the overview;
the GitHub issues are the plan.

- Logic goes in `Packages/ShoppingKit`, not the app: `ShoppingCore` imports Foundation only (no Core Data or UI), and
  `ShoppingStore` (Core Data) wraps every file in `#if canImport(CoreData)`.
- The Core Data model is built in code (`Model.swift`) and must stay CloudKit-compatible: every attribute optional or
  defaulted, every relationship optional with an inverse, no ordered relationships, no unique constraints.
- New objects go in the same persistent store as their `Store` (`ListService.insert(_:alongside:)`), or a shared list
  never gets them.
- Fetch by entity name (`Fetch`, `NSFetchRequest(entityName:)`), not `T.fetchRequest()` or `T(context:)`.
- The UI follows SK1Kit's recipes (`.claude/skills/adopt-sk1kit/SKILL.md`): chassis on every screen and sheet, one orange
  key per screen, live numbers on the LCD. `Scripts/sk1-audit.sh App` must pass.
- `BuckFifty.xcodeproj` is generated by XcodeGen from `project.yml`; don't commit it.
- Builds are warning-free (CI uses `-warnings-as-errors`). Commit subjects use Conventional Commits (`feat: …`, `fix: …`).
- There's no Mac toolchain in cloud sessions: CI's macOS job is the compiler, and its `screenshots` artifact shows the app.
